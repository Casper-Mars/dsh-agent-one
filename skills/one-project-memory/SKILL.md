# 项目记忆

一个项目一个会话的收益来自「记得住」；代价是上下文会涨。这个 Skill 定义记什么、放哪、什么时候压缩。

## 记什么

项目笔记固定四块：

```markdown
## 项目
- project_id / 名称 / 仓库 / 默认分支
- 当前目标与不做什么

## 角色子智能体
- pm: <child_id> 最近任务 <task_id> 结论 <一句>
- cto: <child_id> ...
- dev: <child_id> ...

## 结论
- <日期> <task_id> <结论/产物 material_id>

## 未决
- <问题> / 谁定 / 缺什么
```

## 放哪

- 优先写进项目背景上下文或任务描述可引用的项目笔记文件；不要只留在聊天里。
- 子智能体 id 必须落盘：主会话压缩后仍要能 `send_message` 回去。
- 大段正文放附件/material，笔记只放引用。

## 什么时候压缩

- 上下文过半，或连续完成 3 张以上任务。
- 压缩前先把「结论 / child id / 未决」更新到笔记，再让 harness 压缩。
- 压缩后先读笔记恢复，不凭记忆继续。

## 反合理化

| 借口 | 现实 |
|---|---|
| 我记得住 child id | 压缩后就不记得；必须落盘 |
| 结论写在聊天里就行 | 下次接手的人/会话看不到 |
| 上下文还够，不用记 | 等不够时已经写不进去了 |
